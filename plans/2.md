# Plan for #2: Reject CO2 values outside 0 to 500 g/km

## Goal
Reject new runs whose `co2GramsPerKm` is below 0 or above 500 with HTTP 400 and the
detail `co2GramsPerKm must be between 0 and 500`. Accept both boundary values,
0 and 500. Existing validation and all other run behavior remain unchanged.

## Dependencies (confirmed / plausible / open), each with change: yes | no
- **confirmed — change: yes:** `src/runs.ts`, `validateNewRun`, currently checks
  only that CO2 is numeric; add the inclusive range validation there.
- **confirmed — change: yes:** `test/app.test.ts`, `runs api` tests exercise POST
  validation and should cover below-range, above-range, and both boundaries.
- **confirmed — change: no:** `src/app.ts` already maps `ValidationError` to
  HTTP 400 with its `details` array.
- **confirmed — change: no:** `src/config.ts` has no CO2-related configuration.
- **confirmed — change: no:** `k8s/configmap.yaml` provides no CO2-related value.
- **confirmed — change: no:** `README.md`, `public/index.html`, and `e2e/`
  contain no CO2 validation contract that requires updating.
- **plausible — change: no:** `src/server.ts` and Kubernetes deployment/service
  are unaffected because the rule is domain validation; verify by running the
  existing verification suite.
- **open — change: no:** none identified.

## Tests
- Update `test/app.test.ts` with POST requests proving values below 0 and above
  500 return 400 and the required detail.
- Add coverage proving 0 and 500 are accepted with HTTP 201.

## Environment contract
No environment variable is added or changed. `src/config.ts`,
`k8s/configmap.yaml`, and the README environment table remain unchanged.

## Risks
The validation order could alter the number or ordering of details when a
request has multiple invalid fields. Unit tests and the pipeline’s lint, unit,
build, rollout, stability, smoke, and browser checks should remain green.
